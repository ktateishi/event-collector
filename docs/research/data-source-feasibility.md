# データソース実現可能性調査（2026-08-07時点）

対象: [event-collector.md](../intent/event-collector.md) で確定した5情報源
（X / Instagram / YouTube / 公式サイトNEWS欄 / 個人ブログ）の取得手段。

## 結論（先に要点）

| 情報源 | 公式APIで可能か | 代替手段 | リスク |
|---|---|---|---|
| **X** | △ 可能だが従量課金・無料枠なし | 非公式スクレイピングAPI（Apify/Bright Data等） | 規約違反グレーゾーン・アカウント凍結リスク |
| **Instagram** | ✕ 他者アカウントのキーワード検索は不可 | 同上（非公式スクレイピング） | 同上（Metaはより厳格） |
| **YouTube** | ◎ 公式APIで十分可能 | 不要 | ほぼなし（無料枠内で収まる） |
| 公式サイトNEWS欄 | ◎ 通常のスクレイピング/RSSで可能 | - | ほぼなし |
| 個人ブログ | ◎ 通常のスクレイピング/RSS/検索で可能 | - | ほぼなし |

→ **X・Instagram だけが構造的な壁**。残り3つは技術的に問題なし。

## 詳細

### X（旧Twitter）

- 2026年2月、公式APIはサブスク制から**従量課金制**へ全面移行。新規開発者は
  無料枠なし、$0.005/投稿読み取り（月2,000,000件上限）、$0.015/投稿作成。
- 想定運用（登録キーワード＋AI拡張語で1日数十件検索）だと、月額が
  数千〜1万円規模になり得る（試算は下記）。
- 非公式スクレイピング（Apify等）は $0.15〜$1.50 / 1,000件と大幅に安いが、
  X利用規約違反であり、アカウント凍結・法的リスクを伴う。
- RSS Bridge / Nitter系の無料代替は、X側の仕様変更で頻繁に壊れる。
  個人の趣味用途以外では信頼性なしとの評価が多い。

### Instagram

- Instagram Basic Display API は2024年末に廃止済み。
- 現行の Instagram Graph API は **Business/Creatorアカウントで自分が管理する
  アカウントのデータ**しか取得できない設計になっており、任意の他者アカウントや
  ハッシュタグの横断検索は公式には不可能。
- つまり「知らない発信元」を探す用途には**公式APIが構造的に使えない**。
- 選択肢は非公式スクレイピングのみ（Apify Instagram Scraper等、$1.50〜$2.70/1,000件）。
  Xと同様に規約違反・アカウント制限のリスクを伴う。

### YouTube

- YouTube Data API v3 は無料、1プロジェクトあたり1日10,000ユニットの無料枠。
- 検索（search.list）は1回100ユニット消費 → 1日約100回まで無料で検索可能。
- 本用途（1日数十キーワード検索）は無料枠内に十分収まる。**問題なし。**

### 公式サイトNEWS欄・個人ブログ

- 通常のWebスクレイピングまたはRSS取得で対応可能。技術的な障壁はない。
- 個人ブログの「未知の発信元」発見は、検索エンジン経由のキーワード検索
  （Web検索API、または本セッションのようなAI検索機能）で対応可能。

## コスト試算（Xの従量課金を選ぶ場合の目安）

前提: 登録キーワード15件 × AI拡張後 平均4語 = 60語、1日1回検索、
1検索あたり平均20件読み取り。

- 読み取り数: 60語 × 20件 = 1,200件/日 = 約36,000件/月
- 費用: 36,000件 × $0.005 = **約$180/月（約27,000円/月）**

→ 個人の趣味用途としては高額。運用するなら検索頻度・キーワード数を
大きく絞るか、非公式スクレイピングに切り替える判断が必要。

## 今回のインタビューで確定した要件との関係

[event-collector.md](../intent/event-collector.md) の Out of scope には
「未知のジャンルとの出会い」は入っていないが、「知らなかったを妥協しない」
という核心要件がある。X・Instagramの網羅性はこの核心に直結するため、
ここで妥協するかどうかは設計判断ではなく**ユーザー自身が決めるべき
トレードオフ**（コスト vs 規約リスク vs 網羅性）。
